Problem

Original factory wired 3 of 4 engines to import names that did not exist on disk, and passed device= to a constructor that had no such param. The 9-test suite never called build_pipeline, so it stayed green while the glue was dead.

Solution

Rewrote build_pipeline to map to the actual adapters; created adapters/remote_whisper.py; added device to OpenASRSource; composed path sets source AND transcriber; WhisperStreamingTranscriber now implements the inherited transcribe (was abstract).

ADR: the composed path needs both ports on the Pipeline. A TypeError at run_streaming time (not construction) means a port was not set — the factory smoke test now asserts all four.
  • All four engines build; run_mode asserted per engine (test_engines.py).
  • Deep: model registry keyed by (model_size, device) — loaded once per session.
  • Leak closed: translator no longer hardcoded; _build_translator honors the translate config.

Problem

run_captions calls display.show_partial(seg) on every partial, but the Display ABC only gave a default pass. Every live partial leaked into the void — no live preview. A missing override now fails at construction instead of silently dropping text.

Solution

Made show_partial abstract in ports.py; ConsoleDisplay prints the raw hypothesis; OverlayDisplay buffers it. Run-mode integration test asserts finals only cross the translator.

  • Locality: the live-preview concern now lives in one method per sink.
  • Partials never reach the translator — finals only (verified by test_run_modes).
  • OverlayDisplay is a pure Display adapter: no raw audio, no ASR JSON.

4 · One external coupling still unverified

Problem

_parse_event is a DEFENSIVE HYPOTHESIS, not a verified contract: the OpenASR live JSON event shape is undocumented at the URLs checked (docs/http-api.md → 404; README documents openasr live + the OpenAI-compatible serve API, not the event format) and OpenASR is pre-v1. The parser tolerates plausible field names so a single real openasr live --mic --stream json run surfaces captions; it is the ONLY schema-coupled function. One real line from the user locks the shape.

Solution

Isolate, then validate. The risk is already contained: only _parse_event touches the schema. Install OpenASR, capture one real openasr live --mic --stream json session, and adjust that one function. Nothing else moves.

ADR: do not build UI on a guessed source seam. Validate _parse_event before promising OpenASR quality — the Display port is safe either way (it consumes Translation, never raw JSON).
  • Locality: blast radius of a schema change is one function.
  • Leverage: capture path stable; only the parser is user-gated.
  • WASAPILoopbackSource captures ALL system audio — not Discord-only (Depth B Rust embed, out of scope).

Top recommendation

Validate _parse_event with one real OpenASR run — then build the overlay UI on the stable seam.

The four-port architecture is sound and the glue is now honest (18 tests pass, all engines build). The single open risk is an external contract, not an internal one. Install OpenASR, capture one live session, fix the lone parser, then ship OverlayDisplay (Tier A: windowed/borderless + loopback; exclusive-fullscreen is a ban risk — out of scope).
