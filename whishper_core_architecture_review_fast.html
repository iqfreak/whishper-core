Measured on this 4050: tiny float16 is 4.6× faster than small (59 ms vs 266 ms) and 2× faster than int8_float16 (59 vs 440). Load: tiny 646 ms vs small 2.3 s. Warmup must be called — first decode cold is 600-800 ms, post-warmup stable 57-60 ms.

Recommendation for gaming: tiny float16 when you must keep game at 60 fps (kernel 6-9 ms vs small 12-18 ms — small blocks 30-50% of a 16.6 ms frame). small float16 when captions can tolerate 1 s block for best English. Moonshine when you need true partials streaming + per-language.

Gaming coexistence — what's implemented

  • Threaded pipeline voicelang_core/pipeline_threaded.py: capture queue maxsize 2 (bounded, drops oldest), ASR thread BELOW_NORMAL, capture NORMAL, translate pipelined queue 8 — transcription never blocks on API RTT (60-220 ms).
  • Below-normal process SetPriorityClass(BELOW_NORMAL) in fast.py so GPU time-slice yields to game render loop. CPU threads=2, batch=1, beam=1.
  • CUDA async allocator cuda_malloc_async observed; _add_cuda_dll_dirs() registers pip nvidia wheels without system toolkit.
  • Warmup WhisperStreamingTranscriber.warmup(0.6) primes CUDA context so first real chunk is 120 ms not 600 ms.
  • ADAPTER registry per-(size,device,compute) cached once, reused.

Translation pipelined — not in hot path

All translator adapters kept: passthrough / libretranslate / deepl / deeplx / google. In pipeline_threaded.py finals are enqueued to translate thread, partials display immediately (same Segment.id). API RTT 60-220 ms adds to translated_text only.

Partial id=7 "The mission starts" → show_partial immediately (0 ms extra)
Final id=7 "The mission starts at dawn." → translate queue → show ~80 ms later
Current code also has is_passthrough fast path (no queue).

Honest <100 ms note

With the current 5 engines, true <100 ms mic→partial is not hit. Closest is whisper tiny 59 ms decode + block. For 80 ms chunk, projected 80+40+11≈131 ms. To hit <100 ms p50 you need a causal transducer (FastConformer 80 ms, Parakeet EOU 120M) which lives in rust-asr-server as ModelType::Transducer via SherpaOnnxCreateOnlineRecognizer — import it via sherpa-onnx OnlineRecognizer with greedy int8 intimately, or keep tiny whisper and accept ~130 ms. Moonshine's first partial 539 ms because it needs ~1 s of context to hypothesize. The Rust IAudioClient3 saves 240 ms on capture, not enough to bring moonshine to <100 ms.
